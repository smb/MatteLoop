## Problem Statement

The existing `emoteScript` proves the video-to-transparent-WebP workflow, but it requires terminal use, manual parameter entry, and a full render before visual quality is known. The desktop application must preserve that processing behavior while making the two expensive decisions—choosing the right frame/model settings and choosing the exported time/crop region—visual and reversible.

The application must run as a native-feeling GUI on Windows, macOS, and Linux and be buildable into platform-specific artifacts without requiring end users to install Python or command-line media tools.

## What Makes This Cool

The central experience is not “a form around a script.” It is a visual before/after workshop: drop in a video, scrub any source frame, frame the subject directly, test background removal on exactly that frame, inspect the alpha edge, then render only when the result is convincing.

The quality-saving moment is immediate feedback: the user can answer “lohnt sich dieses Modell mit diesen Einstellungen?” before committing to a long render.

## Constraints

- Cross-platform desktop UI for Windows, macOS, and Linux.
- User-facing default model is `birefnet-portrait`, regardless of the upstream `rembg` default.
- All parameters currently supported by `emoteScript` remain available.
- Initial output format is lossless animated WebP with transparency.
- Preview and full render must call the same crop, segmentation, edge-treatment, and per-frame cleanup functions. Range-global trim is explicitly previewed as an estimate unless bounds for the complete range have already been analyzed.
- Model preparation, preview inference, and final rendering never execute on the Qt UI thread. They intentionally lock editing behind a modal wait dialog that continues to repaint, report the active stage, and offer cooperative cancellation.
- V1 distribution targets CPU inference for predictable packaging. GPU builds are not planned.
- Model weights are downloaded on first use and cached outside the application bundle; they are not embedded in every installer.
- Builds are platform-specific. A macOS `.app` cannot be compiled on Windows, and a Windows `.exe` cannot be compiled on macOS.
- Public artifacts are intentionally unsigned; macOS Gatekeeper and Windows SmartScreen warnings must be documented. Signing/notarization is not planned.

## Premises and Decisions

- **Port the behavior, not the shell:** Python owns the media pipeline. `emoteScript` remains the behavioral reference and rollback path, not a subprocess dependency.
- **Use PySide6 Widgets:** Qt provides the mature cross-platform desktop primitives needed for native drag/drop, custom timeline/crop painting, background workers, file dialogs, and packaging.
- **Use PyAV for video I/O and Pillow/NumPy for image/WebP work:** this removes the end-user dependency on separately installed `ffmpeg`, ImageMagick, and `img2webp` binaries.
- **Use `rembg` as a library:** create one session per selected model and reuse it for all preview/render frames in a job.
- **Use three implementation areas:** `ui/` owns Qt presentation, `core/` owns pure media/domain behavior, and `jobs/` owns orchestration, persistence, downloads, and the isolated segmentation process. Interfaces stay testable without creating five runtime layers.
- **Keep one-window workflow:** source and result dominate the left; one inspector rail holds settings on the right; progress and cancellation remain visible at the bottom.
- **Make temporal cut and spatial crop visual:** the timeline owns In/Out selection; the source preview owns the crop rectangle. Numeric fields mirror both but are not the primary interaction.
- **Preserve source access:** the playhead can scrub the complete original even outside the selected export range.
- **Use explicit inference:** scrubbing updates the original immediately, but `rembg` runs only when the user invokes `Preview Frame`. Any change to playhead, crop, segmentation, edge treatment, alpha cleanup, or framing marks it visibly stale.
- **Ship lossless animated WebP first:** additional formats are outside V1.
- **Define delivery by verified execution class:** V1.0 is the stable local core: all prompt-free local models in the pinned catalog support preview and full render. V1.1 completes the requested public catalog with SAM preview-only and the explicitly labelled `withoutbg` cloud path. The project is not considered feature-complete against the user's “all models” request until V1.1 passes its dedicated tests, but special providers do not block proving or packaging the local core. Custom sessions and ViTMatte are outside the committed scope.
- **Persist the expensive intermediate:** validated post-segmentation RGBA PNGs are promoted before encoding, can be edited externally, and can drive a later Rebuild without decoding or running `rembg` again.
- **Keep sessions disposable:** source, preview, jobs, tokens, and workspace state reset on restart. `QSettings` stores only simple preferences and window geometry; missing or invalid values fall back to current defaults.

## Cross-Model Perspective

An independent Codex design review examined the approved wireframe read-only. Claude review was unavailable because the local Claude CLI was not authenticated.

The review's visual thesis was: “A precision workshop where the subject stays visually dominant and every control quietly explains how it becomes a clean, transparent animation.” It confirmed the workflow and recommended no material structural change.

Accepted refinements:

- Treat the paired preview as one uninterrupted dark canvas, not two equal-weight cards.
- Collapse the large drop zone into a compact source strip after a video is loaded.
- Use one continuous inspector rail with spacing and separators instead of nested bordered panels.
- Keep the processed result visibly stale after frame, crop, model, or parameter changes.
- Report the active render stage—model load, decode, segmentation, post-process, encode, size fit—not just a generic percentage.
- Add a linked inspection lens and hold-Space original/result comparison for alpha-edge inspection.
- Use one “alpha green” accent, restrained geometry, and monospaced telemetry to make transparency itself the brand material.

The suggested automatic inference after a 250 ms scrub pause is intentionally not adopted: explicit `Preview Frame` avoids surprise compute and model downloads while preserving instant source scrubbing.

## Approaches Considered

- **Approach A — Compact PySide monolith:** fastest prototype, rejected because UI, long-running jobs, model lifecycle, and packaging would become tightly coupled.
- **Approach B — Three-area PySide application:** selected because it preserves desktop capability while keeping UI, pure processing, and long-running jobs independently testable without unnecessary runtime layers.
- **Approach C — Flet application:** rejected because its browser-influenced rendering and file-drop/custom-canvas ergonomics are a weaker fit for a media desktop tool.

## Recommended Architecture

### Runtime layers

1. **UI (`rembggui/ui`)**
   - `MainWindow`, source drop strip, paired preview canvas, visual timeline, crop overlay, inspector, model manager, and modal job dialog.
   - Owns widgets and presentation only. It renders immutable state and emits typed user events.
   - Custom-painted timeline and crop widgets install a `QAccessible` factory. Their widget wrapper and virtual children expose standard roles, values, actions, focus, and screen geometry without adding visible overlay widgets.

2. **Core (`rembggui/core`)**
   - Frozen `SamplingSpec`, `CropSpec`, `SegmentationSpec`, `FramingSpec`, and `OutputSpec`; `RenderRequest` composes them into a validated job snapshot.
   - Pure probe/sampling/crop/alpha/framing/timing/fingerprint/validation functions and format-specific encode logic. No Qt widget dependency.

3. **Jobs (`rembggui/jobs`)**
   - Source workers, model manifest/download/cache, exclusive preview/render/rebuild orchestration, settings/workspace persistence, atomic promotion, structured logs, and the spawned `SegmentationProcess`.
   - Adapters hide Qt cancellation, process IPC, platform paths, and pinned `rembg` details behind small contracts.

```text
Qt events ──> pure reducer ──> immutable AppState ──> widgets
                    │
                    └── capability says "start job"
                                  │
                                  v
                       exclusive JobContext
                         │             │
                         v             v
                    core functions   spawned rembg host
                         │             │
                         └────events───┘
                                  │
                                  └──> reducer (matching job_id only)
```

### State model

One immutable `AppState` contains four orthogonal state values:

- `SourceState = EMPTY | LOADING | READY | ERROR`
- `PreviewState = NONE | RUNNING | CURRENT | STALE | ERROR`
- `JobState = IDLE | PREPARING_MODEL | PREVIEWING | RENDERING | CANCELLING`
- `ArtifactState = NONE | VALID | ERROR`

Rules:

- A central pure event reducer is the only place that changes application state. Widget enablement and visible actions are derived capabilities, not independently toggled flags. Worker results carry a job ID; late or superseded IDs are ignored.
- Loading a source is permitted only while `JobState=IDLE`. `Replace…` during active work first offers `Cancel job and replace`; the source changes only after cancellation completes.
- A preview request transitions `IDLE → PREPARING_MODEL` when acquisition/session setup is needed, then `PREVIEWING`; with a ready cached session it transitions directly `IDLE → PREVIEWING`. Success/error/cancel acknowledgement returns to `IDLE`. It is disabled during any non-idle job and there is no hidden queue.
- Render is disabled while preview/model work is running and for SAM. A current preview is recommended but not required: rendering with `PreviewState=NONE|STALE|ERROR` opens `Preview first` (default), `Render anyway`, or `Cancel`.
- Preview, model preparation, final render, and Rebuild are exclusive modal jobs. The entire editor is locked until success, failure, or acknowledged cancellation; the wait dialog alone remains interactive.
- `JobDialog` is a parent-owned, long-lived `QDialog` opened asynchronously with `open()` after setting `Qt.ApplicationModal`; the application never starts an exclusive job through `QDialog.exec()` or another nested event loop. Its signals dispatch typed reducer events, and the dialog lifetime follows the active `JobContext` rather than a blocking call stack.
- A relevant setting/playhead change moves `CURRENT` to `STALE` without deleting the old result; the stale overlay names the changed category.
- Only one inference/render job may use the single segmentation process at a time. There is no multi-session cache in V1; selecting another model evicts the current process before preparation begins.
- Cancel changes the job to `CANCELLING`; controls unlock only after the worker acknowledges. One ONNX inference or encoder call may finish before cancellation takes effect.
- `JobDialog.reject()`, Escape, and any available window-close action are guarded: while a job is active they dispatch `CancelRequested` exactly once and leave the dialog open in `CANCELLING`. Only a matching terminal worker event (`CancelAck`, success, or safely-cleaned-up failure) may close and dispose the dialog; late events with another job ID cannot affect it.

### Worker model

- Qt's UI thread owns every widget.
- Interactive source decoding and background thumbnail/hash work use dedicated single-purpose workers. Background work pauses while an exclusive modal job runs; there is no general-purpose thread pool competing with render.
- Every frame-reading activity owns its own read-only PyAV `InputContainer`: interactive frame worker, thumbnail worker, and render job never share or move a container across threads.
- ONNX session creation/inference is isolated in one spawned `SegmentationProcess` because heavyweight sessions and native cleanup are not reliably memory-bounded inside a long-lived GUI process. It owns exactly one model session and accepts one request at a time through a versioned control `Pipe` plus one reusable shared-memory frame slot. The parent owns and unlinks shared memory. Switching models terminates and joins the process before spawning its replacement, guaranteeing OS-level memory reclamation; frozen entry points call `multiprocessing.freeze_support()`.
- Every operation receives a `JobContext` containing job ID, progress sink, cancellation state, and workspace. Qt workers adapt `requestInterruption()`, downloads adapt `QNetworkReply.abort()`, and the child process returns `CancelAck`; controls unlock only after acknowledgement.
- Progress events contain `stage`, `completed`, `total`, and a human-readable detail. Indeterminate stages remain explicitly indeterminate instead of showing fake percentages.
- Errors cross boundaries as a serializable `AppError` with stable `ErrorCode`, stage, user-message key, technical detail, retry action, and job ID. Tracebacks remain in local logs and never cross into UI state.

### Interaction geometry

- Timeline and crop each derive one immutable `InteractionGeometry` snapshot from `AppState`, logical viewport size, device-pixel ratio, and the current media transform. Geometry calculation is pure presentation logic and never reads mutable widget flags.
- The snapshot contains visual paths/rectangles, pointer and touch hit regions, keyboard focus rectangles, accessible screen rectangles, and explicit source↔widget↔screen coordinate converters. Painting, hit testing, keyboard movement, focus rendering, tooltips, and `QAccessible` adapters must consume that same snapshot; none may repeat coordinate math independently.
- Pointer and touch hit padding expands interaction regions without changing the visible geometry. Overlap resolution is deterministic and tested: the currently focused/dragged element wins, then handles, then playhead/range lines, then the containing region.
- Pure parameterized tests cover resize, zoom, rotation, letterboxing, clamping, and 100/150/200% device scaling before widget-level input tests are added.

## Interface Specification

### Window and hierarchy

- Target default size: 1440×900; usable minimum: 1100×720.
- Left workspace receives approximately 70% of available width; inspector is 340–400 px.
- Before source selection, the top accepts drag/drop and offers `Choose Video…`.
- After load, it collapses to a compact source strip showing filename, dimensions, duration, detected frame rate, file size, and `Replace…`.
- The paired preview uses a shared dark stage. `Original` and `Result` are small canvas overlays, not panel headers.
- Result transparency uses a subdued checkerboard.

### Visual timeline and preview-frame selection

- A viewport-adaptive cached filmstrip represents the complete original video with approximately one thumbnail per 80–100 logical pixels, clamped to 12–48 evenly sampled images. A source-fingerprint-keyed LRU disk cache is capped at 256 MiB; resize generates only missing samples and prioritizes the visible set.
- A playhead scrubs the entire original and moves immediately. The large exact source frame is decoded only after 100–150 ms without further pointer motion; intermediate requests are replaced by the newest timestamp.
- Start and End handles define the render range. Excluded ranges are dimmed; the selected range remains clear.
- If the playhead is outside the render range, the timeline and metadata show `Outside export range`; preview inference is still allowed.
- Timecode and absolute frame-number fields stay synchronized with the playhead. For variable-frame-rate input, timestamp is authoritative and the displayed frame index is informational.
- `Set Start to Playhead`, `Set End to Playhead`, and `Reset Range` are available through compact buttons and timeline context actions.
- Keyboard support: Left/Right steps one exact decoded frame without debounce; Shift+Left/Right makes a larger step; `I` sets Start; `O` sets End; Space is reserved for original/result comparison when focus is on the preview.
- Thumbnail generation is asynchronous and cancelable while the editor is idle, never blocks immediate first-frame display, and pauses for modal preview/render/rebuild jobs. Typical source length is 1–2 minutes, so the bounded scheme is intentionally simple rather than a zoomable multi-resolution index.
- The export interval is `[Start, End)`: Start is included and End is excluded, except that End may equal the probed source duration.
- Start and End are primary. Editing Start leaves End fixed; editing End leaves Start fixed; the displayed Duration recomputes. Editing Duration sets `End = min(source_duration, Start + Duration)`.
- Handles cannot cross and maintain at least one output-frame interval (`1/FPS`). Values snap to milliseconds for display but retain rational timestamps internally.

### Visual spatial crop

- `Crop` toggles a draggable and resizable rectangle over the original preview.
- Eight resize handles and interior drag update `x`, `y`, `width`, and `height` fields live.
- Numeric edits update the overlay in both absolute pixels and normalized source coordinates.
- The crop is clamped to source bounds and honors display scaling, pixel aspect, and rotation metadata.
- `Reset Crop` restores the complete oriented frame. Optional aspect presets are convenience only; freeform crop remains available.
- The processed preview always displays the cropped coordinate system, so it matches render behavior.

### Preview behavior

- `Preview Frame` decodes the current playhead and runs the exact crop, segmentation, edge treatment, and per-frame cleanup used by render.
- It opens the exclusive modal wait dialog; editing remains locked until the result, error, or cancellation acknowledgement arrives.
- With global trim off, framing/padding/stretch matches the rendered frame exactly. With global trim on and no valid range-bounds cache, the result stays on the cropped source canvas and shows the frame-local alpha bounds as a dashed estimate plus `Final framing uses the whole export range`. It does not pretend a one-frame bound equals the animation-wide union.
- After a completed render or an explicit future range-analysis pass, cached union bounds may show exact final framing only while source fingerprint, Start/End/FPS, crop, model, edge, threshold, trim, and padding/stretch settings all match.
- First use of an uncached model changes the action to a model-preparation state and shows download/preparation progress when available, otherwise a truthful indeterminate stage.
- Original and processed images remain side by side at matched zoom and pan.
- A linked inspection lens magnifies identical coordinates in both panes and can reveal the alpha edge on the result.
- Holding Space temporarily shows the original in the result pane; releasing restores the cutout.
- Changing playhead, source, crop, model, edge treatment, alpha-matting inputs, trim, threshold, padding, or stretch overlays `Settings changed — preview again` on the result and disables any implication that the old preview is current. Output path/name/size alone does not stale segmentation, though changing size invalidates any exact final-size framing metadata.
- The result metadata shows model, edge mode, source timestamp, processing duration, and whether the frame lies inside the export range.

### Inspector

Sections appear in consequence order and use progressive disclosure:

1. **Segmentation** — model, edge treatment, model status/size, `Manage Models…`.
2. **Time & Sampling** — Start, End/Duration, output FPS; mirrors timeline values.
3. **Crop & Cleanup** — crop values, alpha-trim threshold, padding, horizontal stretch.
4. **Output** — output directory, filename, maximum size, and final-file collision policy.

Persistent cut reuse is a separate `Workspace` utility (`Use existing cuts`, `Regenerate`, `Open Cut Folder`, `Rebuild from edited cuts`, `Manage Workspaces…`) and is never labelled as output overwrite behavior.

Always visible controls are model, edge treatment, output FPS, selected range, output path, output filename, max size, `Preview Frame`, and `Render Video`. Model-specific parameters, detailed crop numbers, diagnostics, and cache management are disclosed on demand.

## Focused Design Review — Approved UI Contract

The focused review approved the timeline-first loaded-editor direction with a 5/5 rating. Its implementation reference is:

The approved direction makes the filmstrip an editing surface rather than a footer. The full source remains visible, the selected export interval is bordered while excluded frames are dimmed, `IN` and `OUT` handles are distinct from the playhead, and exact time/frame telemetry sits adjacent to the timeline. Original and Result remain side by side inside one shared canvas. The modal-job mockup generated during exploration is supporting evidence only; the selected timeline-first mockup is the approved visual source of truth.

### Presentation hierarchy and action priority

1. Compact source strip: source identity and `Replace…`.
2. Shared Original/Result canvas: visual crop on Original, transparency and preview state on Result.
3. Timeline editor: complete-source filmstrip, selected interval, playhead, exact time/frame, range controls.
4. Inspector: consequence-ordered settings in one continuous rail.
5. Fixed action shelf: `Preview Frame` and `Render Video` remain visible independently of inspector scroll.

Action emphasis is state-dependent without moving either button:

- `PreviewState=NONE|STALE|ERROR`: `Preview Frame` is alpha-green primary; `Render Video` remains enabled when the capability model permits it but is secondary.
- `PreviewState=CURRENT`: `Render Video` becomes alpha-green primary; `Preview Frame` remains visible and secondary.
- Any exclusive job: both editor actions are disabled behind the modal dialog; only the dialog's safe controls remain interactive.

### Exclusive modal job dialog

- Dialog title names the operation: `Preparing model`, `Previewing selected frame`, `Rendering video`, or `Rebuilding from edited cuts`.
- Stage label and detail are separate from the progress indicator. Known work shows `completed of total`; session creation and other unknowable stages use an indeterminate indicator without a percentage.
- The editor is application-modal, visually dimmed, removed from the active tab order, and never unlocks while cancellation is pending.
- `Cancel` is initially focused only when a job was invoked by pointer; keyboard invocation preserves a predictable dialog reading order of title → stage → detail → progress → `Show details` → `Cancel`.
- Escape is equivalent to activating `Cancel`, never an unsafe close. The window close control is omitted or disabled while native work cannot stop immediately.
- The dialog uses asynchronous `QDialog.open()` with `Qt.ApplicationModal`, never `QDialog.exec()`. Its guarded `reject()` converts Escape and close attempts into one reducer-owned cancellation request; it cannot accept or close while `JobState=CANCELLING` and closes only after the matching terminal job event.
- Accessibility announcements occur on stage changes and coarse progress boundaries, not once per frame. `Cancelling…`, success, and failure are each announced once.
- Preview success closes automatically and moves visible focus to Result. Render success closes automatically and moves focus to the success banner. Failure becomes the structured error dialog only after job cleanup is safe.

### Minimum-window and high-DPI contract

- `1100×720` is a hard minimum in Qt logical pixels; the app does not introduce a second stacked or tabbed layout below it.
- At the minimum, the inspector is exactly 340 px; it may grow to 400 px as the window widens. Original and Result remain side by side in the remaining workspace.
- The inspector contains a vertically scrollable settings viewport plus a fixed 104 px action shelf. The action shelf never scrolls away. Workspace utilities belong to the scrollable content, not the fixed shelf.
- The timeline retains at least 176 px height: filmstrip, range/playhead layer, time ruler, and compact controls remain separately targetable. Canvas height absorbs vertical resizing before timeline semantics are removed.
- The source filename truncates in the middle while preserving its extension. Duration and dimensions remain visible before file size or less important telemetry.
- There is no application-level horizontal scrollbar. Long paths use middle elision and expose the complete value through accessible description and tooltip.
- At 100%, 150%, and 200% scaling, layout measurements use logical pixels; raster frames remain pixel-accurate and checkerboard/crop strokes remain at least one physical pixel.

### Keyboard and assistive-technology contract

- Stable tab order: source strip → Original canvas/crop → Result canvas → timeline/playhead → range controls → inspector sections → fixed Preview/Render shelf.
- Every custom canvas/timeline object exposes an accessible name, role, current value, and value text. Required names include `Crop rectangle`, all eight crop handles, `Export start`, `Export end`, and `Preview frame playhead`.
- Timeline and crop each provide a custom `QAccessibleInterface` registered through `QAccessible.installFactory`; the parent widget uses the `QAccessibleWidget` convenience path and exposes virtual children for IN, OUT, playhead, crop rectangle, and all eight crop handles. Interactive children implement the applicable value and action interfaces, and their accessible rectangles use the same widget-to-screen transform as painting and hit testing.
- Reducer or geometry changes emit the matching accessibility focus, value, name/description, visibility, and location events through `QAccessible.updateAccessibility`. Accessibility state is an adapter over the immutable editor state, never a second mutable copy of control values.
- Timeline keyboard behavior remains Left/Right one frame, Shift+Left/Right larger step, `I` set Start, and `O` set End. Shortcuts operate only in the editor context and never while typing in a field.
- Crop has an equivalent numeric editing path at all times. When the overlay is focused, arrows move it by one source pixel and Shift+arrows by ten; focused handles resize with the same increments. Bounds are announced after the operation settles.
- Space performs hold-to-compare only while Result has focus. It never steals Space from buttons, fields, dialogs, or timeline playback controls.
- Focus uses a 2 px alpha-green ring with a dark separation stroke and at least 3:1 contrast against adjacent surfaces. Text meets WCAG AA contrast: 4.5:1 normal text, 3:1 large text; status and control boundaries meet 3:1.
- Primary controls are at least 40 logical pixels high and have an effective 44×44 target through hit padding. Visual timeline/crop handles may remain compact but expose at least a 24 px pointer hit region and a 44 px touch hit region.
- Status never relies on green/amber/red alone. Icons, labels, and accessible descriptions carry the same meaning.
- System reduced-motion preference removes the 180/240 ms disclosure/result transitions; no workflow depends on animation.

## Parameter Mapping

| Script option | Type, unit, default | GUI and exact rule |
|---|---|---|
| `-i INPUT` | Existing readable local file; required | Drop target/file picker. Unicode and spaces supported. |
| `-o OUTPUT` | Path; default `<source-stem>.webp` | Directory picker + filename. After first install, directory defaults to the source directory; once the user explicitly chooses another directory, that choice persists for later sources. |

| `-s START` | Non-negative timestamp; default `0` | Start handle/field, inclusive, `< source duration`. |
| `-d DURATION` | Positive seconds; default source remainder | GUI displays End and editable Duration. Duration edit sets End; interval is `[Start, End)`. |
| `-c W:H:X:Y` | Four non-negative integers in oriented source pixels; default full frame | Visual rectangle plus `x/y/width/height`; width/height `>=1`; rectangle must remain inside source bounds. Applied before `rembg`. |
| `-t` | Boolean; default off | `Global trim` checkbox. One alpha-union bounding box is applied identically to every frame. |
| `-a PERCENT` | Float `%`, `0..100`; default `2.0` | Used only when calculating the global trim union; pixels with alpha below the threshold do not contribute. |
| `-p PIXELS` | Integer px, `>=0`; default `0` | Equal transparent border on all four sides after trim. |
| `-x FACTOR` | Float multiplier, `>0`; default `1.0` | Horizontal resize after trim and padding; height is unchanged; width rounds with `floor(w*factor+0.5)`. |
| `-M MB` | Float MiB, `>=0`; default `0` (off) | Optional maximum final file size; bytes target is `MB*1024*1024`. |
| `-r` | Rebuild mode; default off | Enabled only when a matching cached cut-frame set is complete and valid. Skips decode and `rembg`, then reruns trim/padding/stretch/encode. |
| `-F` | Force mode; default off | `Regenerate cut frames…` explicitly confirms replacement, builds a staged set, and retires the old exact-key cache only after the replacement validates and is atomically promoted. Mutually exclusive with Rebuild. |
| fixed `MIN_DIM` | `128 px` per final dimension | Initial post-processing dimensions and every auto-fit result must both be at least 128 px. |

Processing order is fixed: orient source → input crop → FPS sampling → `rembg`/edge treatment → optional global trim → padding → horizontal stretch → lossless WebP → optional proportional size fit.

The job workspace is `<output-directory>/.rembggui-work/` with two lifecycles:

- `scratch/<job-id>/` contains disposable decode/render/autofit files. It is removed after completion, cancellation, or handled failure unless diagnostic retention is explicitly chosen; abandoned scratch older than 24 hours is offered for cleanup at launch.
- `cuts/<cache-key>/` contains persistent, editable post-segmentation PNGs, `manifest.json`, and derived union metadata for Rebuild. It is never auto-deleted. `Manage Workspaces…` shows size, source, last use, edited/pinned state, and explicit deletion. Above 20 GiB total, the app warns before creating another cache and opens cleanup; it still never deletes manual work automatically.

Fingerprinting has two tiers. A fast provisional fingerprint (canonical path, size, mtime, and head/tail chunks) may key UI metadata and thumbnails, but it is never trusted for persistent cut reuse. Before a cut set is reused or promoted, the app computes the complete source SHA-256 as a streaming background read and rejects a source that changes while hashing.

The authoritative cache key includes the complete source SHA-256, sampled range/FPS, crop, model ID, model-weight SHA-256, pinned `rembg` version, application pipeline-schema version, orientation/color-conversion version, and edge settings. Regeneration writes a new staged cut directory, validates every PNG and its manifest, then atomically promotes it before framing or WebP encoding begins; an older valid cache remains untouched until promotion succeeds. A later encoding failure therefore never discards expensive valid cuts. Force never targets a directory not named by the fully resolved cache key.

`Open Cut Folder` exposes cut PNGs. Before every Rebuild, the app rescans sorted names and requires the manifest frame count, sequential naming, identical RGBA dimensions, readable PNGs, and current content hashes/mtimes. External edits mark the cache `manually edited`, invalidate union/framing metadata, and set `PreviewState=STALE`. In this state the original model preview is labelled `Model preview — rebuild uses edited cut frames`; choosing a timeline sample that maps to a cached cut also offers `Show edited cut`. Exact preview/render parity is claimed only for that edited cut view, not for the obsolete model result.

Rebuild never reads files that an editor may still be changing. At job start it creates an immutable scratch snapshot, preferring reflink/copy-on-write and otherwise copying the complete validated set. It verifies source metadata before and after snapshot creation; any concurrent save aborts with `Cut frames changed — retry Rebuild`. Saves made after a valid snapshot affect the next job, not the running one.

Normal mode protects an existing matching cut set and asks whether to Rebuild, Regenerate, or Cancel. Rebuild skips decode/segmentation and consumes the validated persistent cut set; Regenerate/Force stages a replacement safely.

Output collision is separate from Rebuild/Force. A final-path collision always offers `Replace`, `Choose another name`, or `Cancel`; Replace writes a sibling temporary file and atomically swaps only after validation.

Auto-fit preserves the script algorithm: encode at source post-process size, then for at most 12 iterations choose `step = min(0.97, sqrt((target_bytes*0.94)/current_bytes))`, multiply the cumulative scale, clamp so both dimensions remain at least 128 px, always resize from the unscaled post-process frames, and fail clearly if the target remains impossible at minimum size.

The app never silently upscales or adds unrequested padding to satisfy the 128 px invariant. A small source crop is allowed only if the configured padding/stretch produces final dimensions of at least 128×128. When global trim is enabled, dimensions are validated after the union bound is known; a sub-128 result fails before encode and suggests reducing trim/increasing padding. An entirely empty range-wide alpha union fails the job, matching the script, and suggests lowering the alpha threshold or changing model/frame range.

Hard format/implementation guards are validated before allocating render frames and again after union trim: final width and height must each be `128..16383`, sampled frame count must be `1..100000`, and the final RIFF WebP must be smaller than 4 GiB. The preflight uses the no-trim worst-case dimensions `encoded_width_max = round((crop_width + 2*padding)*stretch_x)` and `encoded_height_max = crop_height + 2*padding`; values outside the guards are rejected even if a later trim might have made them smaller. An encoded result reaching the byte cap fails validation before atomic replacement.

## Processing Pipeline

### Source probe and frame access

1. Open the source with PyAV and validate a decodable video stream.
2. Read duration, time base, average rate, dimensions, rotation, pixel aspect, and color metadata.
3. Build a timestamp-based seek index opportunistically; do not assume constant frame rate. Each decoded frame owns the display interval from its PTS through the next frame's PTS.
4. Decode a preview by choosing the source frame whose display interval contains the requested timestamp (the latest frame with `PTS <= requested`; use the first frame before the first PTS). Report requested and actual PTS.
5. Generate the bounded 12–48-image timeline set on its dedicated worker and cache it by provisional fingerprint; replace the key after the complete source SHA-256 is known.

Pointer scrubbing updates the playhead/filmstrip immediately and coalesces exact source-frame decode behind a 100–150 ms quiet-period timer. Frame-step keyboard commands bypass that timer. Each decode request carries a monotonically increasing ID so an older result cannot replace a newer playhead frame.

For a render interval `[S,E)` at integer output rate `F`, construct target timestamps `t_n = S + n/F` for every integer `n >= 0` where `t_n < E`. At each target choose the source frame whose display interval contains `t_n`; duplication is intentional when output FPS exceeds source cadence. Expected frame count is `ceil((E-S)*F)` subject only to rational-boundary equality, which is tested without floating-point comparisons.

WebP stores integer-millisecond delays, so frame `i` receives `delay_i = round((i+1)*1000/F) - round(i*1000/F)`. This distributes rounding (for example 16/17 ms at 60 fps) and keeps cumulative encoded time within 0.5 ms of `N/F`. It intentionally corrects the Bash script's accumulating fixed-delay drift while preserving the requested FPS and lossless output.

### Preview

1. Freeze the current spec values and playhead into a preview request with its own fingerprint and job ID; open the exclusive modal wait dialog.
2. Decode and orient the current source frame in the preview worker's private PyAV container.
3. Apply the visual crop using the same pure transform used by render.
4. Copy the RGB(A) input into the parent's reusable shared-memory slot, send the versioned request over the control Pipe, and run the selected reusable `rembg` session plus edge treatment in the child process.
5. Validate the response job/protocol ID and return the exact pre-global-trim RGBA result plus timing/stage metadata.
6. If global trim is disabled, apply padding/stretch exactly. If it is enabled, use exact cached range-union bounds only when their targeted fingerprint matches; otherwise show the pre-trim canvas and a clearly labelled local-bounds estimate.

### Full render

1. Freeze all specs into an immutable `RenderRequest`, compute targeted fingerprints, allocate a private `JobContext`, and open the exclusive modal wait dialog.
2. Decode only the selected Start–End interval and sample by timestamp at the requested output FPS using the render job's private PyAV container.
3. Apply orientation/crop and process each frame through the same segmentation function and shared-memory protocol used by preview.
4. Write post-segmentation RGBA frames into a job-private staged cut directory while incrementally computing union alpha bounds.
5. Validate every staged frame and manifest, then atomically promote a complete copy/snapshot into `cuts/<cache-key>/` before encoding. The running job retains its private immutable staged set, so external edits affect only a later Rebuild.
6. In a second bounded-memory pass, apply the shared union crop, padding, and horizontal stretch so the animation does not jump frame to frame.
7. Encode lossless animated WebP with the cumulative rational-rounding delay sequence and infinite loop metadata.
8. If a maximum size is set, iteratively reduce dimensions and re-encode until the target is met or the 128 px minimum is reached.
9. Validate that the artifact opens, is animated when multiple frames exist, has expected frame count/duration within tolerance, and contains alpha.
10. Write to a sibling temporary output and atomically rename only after validation. A failed or cancelled job never replaces an existing good output or a promoted valid cut set.

```text
normal render: source → private decode/rembg cuts → validate → promote persistent cuts
                                                       │
                                                       └→ private framing/encode → validate → atomic output

edited rebuild: persistent edited cuts → validate → immutable scratch snapshot
                                                       │
                                                       └→ framing/encode → validate → atomic output
```

Disposable `scratch/<job-id>` files are deleted on normal completion, cancellation, and handled failure after the structured error has been copied to the application log. `Keep diagnostic workspace` is an explicit opt-in on the error dialog; retained diagnostics are labelled and must be deleted or reconfirmed before another job starts. Validated `cuts/<cache-key>` artifacts persist for Rebuild under the explicit workspace policy above. On crash, only abandoned scratch is offered for automatic cleanup; a staged cut set is either validated/promoted or removed while the prior complete set survives.

Before render, let `N = sample_count`, `P_infer = N*crop_width*crop_height`, and `P_encode = N*encoded_width_max*encoded_height_max`, where the encoded maximum includes worst-case no-trim padding/stretch. The advisory preflight uses `cut_stage_bytes = P_infer*4*1.10`, `render_stage_bytes = P_encode*4*1.10`, `webp_upper_bytes = P_encode*4.10`, and `estimated_required = cut_stage_bytes + render_stage_bytes + 2*webp_upper_bytes + 512 MiB`; Rebuild also includes one conservative full-copy estimate for its immutable snapshot. Max-size does not reduce the estimate because that target may be impossible. Insufficient free space never blocks a job.

The UI always shows sample count, both pixel-frame totals, estimated required/free disk, and estimated time. It presents a clear confirmation when estimated free space is insufficient or when either pixel total exceeds 2.5 billion, `estimated_required > 20 GiB`, or projected CPU time exceeds 30 minutes; the user may always continue. Disk-full failures remain staged and cannot replace existing output or persistent edited cuts. Only jobs with both `P_infer` and `P_encode <= 2.5 billion` are in the supported performance envelope; larger confirmed jobs are best-effort.

Time projection uses the current model's measured preview inference time multiplied by sample count plus benchmarked decode/encode overhead; without a current preview it uses the slower of the release benchmark and available local history. The pipeline holds at most three full-resolution RGBA frames outside the ONNX session. A packaging spike must prove that the chosen Pillow animated-WebP path consumes frames lazily and retains only compressed animation data. If it materializes the RGBA sequence, the implementation must use PyAV's bundled `libwebp_anim` path or another in-process streaming libwebp binding before feature work continues—reintroducing an external CLI is not acceptable.

## Failure and Edge Cases

- Missing, unreadable, zero-duration, audio-only, or corrupt source: reject with actionable details.
- Variable-frame-rate media: timestamp is canonical; never calculate seek solely as `frame / fps`.
- Source changes while the complete SHA-256 is being computed: discard the hash and provisional cache association, then ask the user to reload the source.
- Rotation and non-square pixel metadata: normalize before crop coordinates are established.
- Very short ranges or output FPS yielding one frame: create a valid still WebP and explain that the range produced one output frame.
- An individual fully transparent frame is retained if other frames make the range union non-empty. If the complete range union is empty while global trim is on, fail before post-processing with threshold/model guidance; with trim off, transparent frames remain valid.
- Foreground touching every edge: union trim becomes full frame; padding remains bounded.
- Crop/trim/padding/stretch derives a dimension below 128 px: fail before encode; never silently upscale or invent padding.
- Model unavailable/offline/download interrupted: retain partial-download safety, present retry, and do not begin render.
- Model checksum mismatch: delete the `.part` file, never initialize it, and identify the affected model/version in the error.
- Cloud token rejected, quota exhausted, proxy blocked, or TLS failure: stop before subsequent frames, do not retry automatically, clear token on authentication failure, and keep any existing output untouched.
- Disk estimate exceeds free space: warn and require confirmation but allow the job; actual disk exhaustion raises a staged error before final rename and preserves every pre-existing output and persistent edited cut set.
- Memory pressure: keep decoded/processed frames bounded and use disk intermediates; never retain the whole video as RGBA arrays.
- Segmentation process crash or protocol mismatch: invalidate the shared-memory response, terminate/join the child, unlink parent-owned memory, return a structured retryable error, and create a fresh child only on explicit retry.
- Cancellation: stop after the current non-interruptible inference/encode unit, clean partial output, and leave source/settings intact.
- Application close during work: require `Cancel job and quit` or `Keep working`.
- Settings changed after preview: stale result remains inspectable but cannot masquerade as current.
- Cloud model selection: require a one-time per-job confirmation that frames leave the machine.
- Preview requested during render/model preparation: action is disabled with the active stage visible; no request is queued.
- Replace requested while cancellation is pending: replacement remains disabled until worker acknowledgement.
- External editor saves during Rebuild snapshot creation: reject the unstable snapshot and offer retry; edits after snapshot completion are intentionally deferred to the next Rebuild.

## Test Strategy

The automated target is 42 technical path groups in `core/` and `jobs/`; the 8 GUI/user-flow groups and 2 packaging groups are explicit manual release checks. Tests use pytest with synthetic public fixtures only. Hypothesis, a hard coverage percentage gate, and a required pytest-qt suite are intentionally absent; coverage may be reported informationally.

### Automated unit tests

- Frozen spec validation and targeted preview/cut/render fingerprints.
- Pure reducer transitions, derived capabilities, stale-preview invalidation, modal job states, cancellation acknowledgement, and rejection of late job IDs.
- Serializable `AppError` mappings and retry actions.
- Rational timestamp grids, `[Start, End)` boundaries, VFR display-interval selection, duplicated high-rate samples, cumulative WebP delay rounding, and total duration.
- Crop transforms under scaling/rotation/DPI; timeline range invariants; alpha union, empty masks, thresholding, padding, stretch, max-size solving, and output validation.

### Automated integration tests

- Generate tiny constant- and variable-frame-rate public fixtures with known colors, motion, rotation, pixel aspect, and duration; do not store or require real portrait/hair footage.
- Exercise separate PyAV containers for frame, thumbnail, and render workers and prove stale decode results cannot replace the current playhead frame.
- Exercise the versioned Pipe/shared-memory protocol using a deterministic fake segmentation child: one request in flight, cancellation acknowledgement, child crash, protocol mismatch, cleanup, and restart.

- Validate still and animated WebP alpha, loop, timing, dimensions, stable union crop, impossible size targets, staged writes, and atomic replacement.
- Test manifest download with a local HTTP fixture: byte progress, interruption, checksum mismatch, atomic promotion, cached offline reuse, version namespaces, and in-use removal guards. Real model weights are excluded from ordinary test runs.
- Test persistent-cut promotion before encode, failed encode after promotion, external edit detection, immutable Rebuild snapshot, editor-save race, invalid PNG sets, union invalidation, and preservation of the previous valid cache.

### Manually started release qualification

Real models, the advertised codec matrix, memory/streaming stress, and frozen artifacts run only in a manually started public GitHub Actions release workflow—not on pull requests and not nightly. Native jobs build Windows x86_64, macOS x86_64, macOS arm64, and Ubuntu x86_64 artifacts and then:

1. launch the packaged application without system Python or external media CLIs;
2. decode every advertised synthetic container/codec/color/orientation fixture;
3. acquire and verify each local model into an isolated cache, run one preview plus a two-frame render, then repeat offline;
4. encode/reopen a two-frame alpha WebP and run the fixed 60/300/3000-frame plus 4K memory stress cases;
5. execute the manual GUI checklist on candidate artifacts and record pass/fail notes;
6. generate third-party notices for Qt/PySide6, PyAV/FFmpeg codecs, libwebp/Pillow, ONNX Runtime, fonts, `rembg`, and model licenses before publishing unsigned artifacts.

V1.0 cannot claim all prompt-free local models until this manual workflow passes on every target architecture. V1.1 separately checks SAM prompts and the `withoutbg` consent/auth/error contract; live cloud calls never run for untrusted contributions.

Parallel lanes after the scaffold:

- **Lane A:** core contracts → media primitives → render/framing core.
- **Lane B:** frozen runtime spike → segmentation/model jobs → render orchestration.
- **Lane C:** timeline/crop widget shell can start against frozen interfaces, then waits for Lanes A+B before GUI/preview integration.

Launch Lanes A and B in parallel worktrees after the scaffold. Lane C may build visual widgets in parallel once spec/reducer interfaces are frozen. Merge A+B before connecting preview; implement Render/Rebuild integration sequentially because it touches both `core/` and `jobs/`. Qualification and V1.1 run last.

Conflict flags: Lanes A and C both touch source/crop contracts if interfaces are not frozen first; Lanes A and B meet in Render/Rebuild. Keep those handoffs sequential rather than resolving semantic merge conflicts after the fact.
