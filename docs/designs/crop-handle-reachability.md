# Design: Reachable crop handles

Generated by /office-hours on 2026-09-03, reviewed the same day
Branch: chore/crop-handle-design
Repo: smb/MatteLoop
Status: REVIEWED

## Problem Statement

The crop editor works, but its handles are hard to grab. Two independent causes,
both in the geometry layer:

**1. The frame is fitted flush to the widget border, so there is no room for a
handle.** `MediaTransform.scale` (`src/matteloop/core/geometry.py:311`) is
`min(viewport.width / display.width, viewport.height / display.height)`. On the
constrained axis the content rectangle touches the widget edge exactly. With the
default crop (the whole frame) the handle centres therefore land *on* that edge:
the 8x8 markers built at `geometry.py:586` are half-clipped, and
`_effective_target` (`geometry.py:928`) clamps the 24 px pointer region wholly
inward. Approaching the edge from outside hits the `PreviewStage` layout margin,
which is not a canvas at all.

**2. Between the handles, the border is not a drag target.** Each handle owns
one 24x24 box. A left edge has three of them (two corners plus `west`), so on a
225 px edge roughly 72 px resize and the remaining ~150 px fall through to the
`"crop"` entry in `priority` (`geometry.py:613`) and translate the whole
rectangle instead.

## What already exists

- `_TimelineTransform.inset` (`geometry.py:676`) — an inset field with a
  build-time clamp already exists on the sibling transform in this file.
  `MediaTransform.inset` follows its shape rather than inventing one.
- `_effective_target(rect, viewport, minimum)` (`geometry.py:928`) already grows
  a rectangle to a minimum size and clamps it into the viewport. The edge bands
  reuse it; they must not be built directly (see Constraints).
- **`tests/ui/test_crop_canvas.py:129-141` already guards the agreement between
  what Qt paints and what the geometry computes**, on all four values:
  `content_rect` width, height, x and y against `canvas.pixmap()`. This matters
  for the approach below: the two computations are not unguarded.

## Constraints

- `core/geometry.py` is Qt-free and deterministic. The geometry belongs there,
  not in event handlers.
- **The edge bands must be produced through `_effective_target`.** Building them
  directly skips its viewport clamp and breaks
  `test_hit_targets_use_the_full_viewport_when_it_is_below_minimum_size`
  (`tests/core/test_geometry.py:153`), which asserts every target collapses to
  the whole viewport when the widget is smaller than one target.
- `core/geometry.py` is frozen at 1057 lines in `scripts/guardrails-baseline.json`.
  Growth was agreed with the maintainer during review, which is the order
  `docs/engineering-guardrails.md:288` requires.
- Verification: `uv run ruff check . && uv run mypy src &&
  QT_QPA_PLATFORM=offscreen uv run pytest -q`

## Premises

1. The reported symptom is the crop drag surface, not the file drop zone.
   Drag-and-drop lives in `ui/source_strip.py:95`; `CropCanvas` accepts no drops.
2. Reachability does not depend on the exact gutter width. Measured against
   `_effective_target` at viewport 100: a 16 px gutter leaves 12 clickable
   pixels outside the image, an 8 px gutter leaves 8. The clamp keeps the whole
   gutter inside the band either way. An earlier draft asserted
   `_MEDIA_INSET >= _POINTER_TARGET / 2`; that relationship is not what carries
   the fix, and the runtime clamp violates it on small viewports while a
   constant-comparison test would stay green. Test reachability, not the ratio.

## Recommended Approach

### 1. One constant, read in two places, guarded by the test that already exists

`MediaTransform` gains an `inset`, and `CropCanvas` passes `_MEDIA_INSET` both as
that inset and as its layout contents margins. `_update_pixmap`
(`preview_canvas.py:200`) shrinks the scaling box by the layout margins and Qt
centres the result, which lands in exactly the rectangle `content_rect` predicts.

It is one number read twice, not two numbers kept in step, and
`test_crop_canvas.py:129` asserts the two results match. That test also
discharges the zoom risk: `MediaTransform` carries `zoom` and `pan` fields that
nothing sets today, and the day someone sets them Qt will not scale the pixmap
to match — so the test goes red at the moment the assumption breaks, which is
the right moment.

An earlier draft had `CropCanvas` paint the frame itself so that one snapshot
placed everything. It was dropped: it removes a working guard in order to
rebuild the property that guard already provides, and it drags in a scaled
pixmap cache, a paint-order constraint against the crop guard, and device pixel
ratio invalidation across monitors — three failure modes that do not otherwise
exist.

### 2. `MediaTransform.inset`, clamped where the sibling clamps

```python
inset = min(self.inset, self.viewport.width / 4, self.viewport.height / 4)
object.__setattr__(self, "inset", inset)
```

`scale` then fits into `viewport - 2 * inset` on both axes, and `content_rect`
stays centred in the full viewport so every widget coordinate remains
widget-absolute.

`inset` defaults to `0.0` and only the crop display geometry passes a non-zero
value. This is not cosmetic: `crop.py:139` builds a `MediaTransform` as a
unit-scale orientation transform whose viewport equals the display size exactly.
A non-zero default would shrink that fit and corrupt every oriented-coordinate
conversion.

The clamp is not decorative either: `crop_canvas.py:264` builds the viewport as
`SizeF(max(1, self.width()), max(1, self.height()))`, and those `max(1, ...)`
exist because Qt hands the widget through at zero width during layout. Without
the clamp, `SizeF` raises, `_rebuild_geometry` swallows it into
`self._geometry = None`, and the overlay silently disappears until the next
resize.

### 3. Full-length edge bands

In `build_crop_geometry`, the pointer and touch rectangles for `north`, `south`,
`east` and `west` span the whole crop edge instead of a square — west covers
`x ∈ [left - 12, left + 12]`, `y ∈ [top, bottom]`. They are produced through
`_effective_target`, per Constraints. The four corners keep their squares and
keep winning, because `priority` already lists them first. `visual` is untouched:
the markers stay 8x8; only what counts as a hit changes.

### 4. The four sizes get names

`_HANDLE_MARKER = 8.0`, `_POINTER_TARGET = 24.0`, `_TOUCH_TARGET = 44.0`,
`_MEDIA_INSET = 16.0` as module constants beside `_CROP_HANDLES`. The guard
against someone trimming the gutter is the reachability test below, not an
inequality between two of the constants — see Premise 2.

## NOT in scope

- **Painting the frame from the geometry snapshot** — see §1. Worth revisiting
  the day zoom or pan is wired up, and `test_crop_canvas.py:129` will say when.
- **Device pixel ratio on the previews** — `_update_pixmap` scales to logical
  points and never calls `setDevicePixelRatio`, so both previews are soft on
  Retina while `StatusLabel` (`preview_canvas.py:95`) already does it right for
  icons. Real, visible, and unrelated to crop handles. TODO candidate.
- **A resize cursor or hover affordance on the edge bands** — full-length bands
  change what a click on the middle of an edge does, with no visible signal.
  TODO candidate.
- **Handles offset outward from the crop edge (Figma style)** — cosmetic; needs
  the focus-ring path reworked.
- **Wiring up zoom and pan** — the fields exist; nothing here exposes them.

## Failure modes

| Path | Failure | Test | Handling | Visible? |
|---|---|---|---|---|
| `MediaTransform.__post_init__` | viewport below `2 * inset` | new | clamp (§2) | would be silent |
| `MediaTransform` in `crop.py:139` | a non-zero default inset | new | default `0.0` (§2) | would be silent |
| `build_crop_geometry` | band escapes the viewport | `test_geometry.py:153` | `_effective_target` | would be silent |
| paint vs geometry | the two fits disagree | `test_crop_canvas.py:129` | existing guard | would be silent |

No critical gap: every silent failure above is closed by a clamp or a default,
and each is paired with a test.

## Test plan

One existing test needs its expected numbers updated, not a rewrite:

- `tests/ui/test_crop_canvas.py:129` and `:146` both pin `transform.scale` to
  `478 / 1280`. The inset changes the fit, so both constants change. The
  structure of `:129` survives untouched and keeps guarding §1.

The core geometry tests are unaffected: `test_geometry.py:66`, `:111`, `:167`
and `test_crop.py:58` build their `CropGeometryState` without an inset, and the
field defaults to `0.0`.

New tests:

1. `test_geometry.py` — `content_rect` is inset on both axes.
2. `test_geometry.py` — `inset` is clamped at a 1x1 viewport and the geometry
   still builds.
3. `test_geometry.py` — a `MediaTransform` built without an explicit inset is
   unchanged from today, so `crop.py`'s orientation transform is unaffected.
4. `test_geometry.py` — parametrised over several gutter values: a point just
   outside the content rectangle hit-tests to the adjacent edge handle.
5. `test_geometry.py` — a point a quarter of the way down the left edge
   hit-tests to `west`, not `crop`.
6. `test_crop_canvas.py` — a drag started outside the frame emits `CropChanged`.

## Implementation order

1. `core/geometry.py`: named constants, `MediaTransform.inset` with the clamp
   and the `0.0` default, inset-aware `scale`, plumbed through
   `CropGeometryState`.
2. `core/geometry.py`: full-length bands through `_effective_target`.
3. `ui/crop_canvas.py`: layout margins and the matching `inset` argument.
4. Update the two scale constants; add the six new tests.
5. `uv run python scripts/check_guardrails.py --update`, naming the reason and
   the new figure in the commit body.

Sequential — every step touches the geometry or depends on it.
